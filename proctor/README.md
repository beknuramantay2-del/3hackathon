# Кейс №3 — локальный CV-прокторинг без встроенного теста

По умолчанию открывается **камера + детекты + HEAD/GAZE + события**, не страница с вопросами. Страница-заглушка отключена. Измерения не зависят от запуска экзамена или прохождения 20-секундной калибровки.

## Запуск

Python **3.10–3.11** (FaceMesh API). Из корня репозитория:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r proctor/requirements.txt
python -m proctor.tools.fetch_weights
python -m proctor.main
```

Для слабого устройства: `python -m proctor.main --perf weak`.
Для показа входного видео: `python -m proctor.main --video video.mp4` — источник помечается VIDEO REPLAY, не выдаётся за камеру.

Зависимости и веса установить заранее. При отсутствии весов YOLO показывает ошибку, а FaceMesh и видео не скрываются. Автоматического скачивания при offline=true и mock-детектов нет.

## Как пользоваться

1. Сядьте прямо и нажмите **«Настроить взгляд · 10 с»**. Следуйте пяти точкам CENTER/LEFT/RIGHT/UP/DOWN глазами, не поворачивая голову. Настройка больше не начинается неожиданно по первому кадру.
2. Шаги сопровождаются звуком и подсказкой. Переходы/моргание/выбросы отбрасываются; явный поворот головы не обучает направление глаз. Неразличимые позы перечисляются — это не «все успешно».
3. **«Обновить центр · 2 с»** — короткая нейтральная настройка после изменения положения. Она не заменяет измерение пяти персональных направлений. До принятого центра предупреждения HEAD/GAZE выключены, телефон и присутствие работают независимо.
4. На основном экране две кнопки: настройка взгляда и завершение. Центр 2 с — в «Настройках». Большое изображение камеры отображается целиком, без обрезки и плашки поверх нижнего края. Под ним — отдельные стрелки **ГЛАЗА / ГОЛОВА**, присутствие, телефон, реальный таймер удержания и события на русском. Направление также видно поверх камеры; возле читаемых глаз — рамки/зрачки/стрелки.
5. Жёлтый телефон = кандидат, красный = подтверждённые наблюдения, серый = только прогноз. Confidence **не является точностью в процентах**. Частичному телефону может помочь свежая рука + серия наблюдений либо согласие общего поиска и ROI + более долгое подтверждение. Модельный score не повышается искусственно.
6. Во вкладке **«Настройки»**: фактические измерения и отдельно удержание бокового взгляда (по умолчанию 2 с) / вверх-вниз (3 с). Длительный DOWN имеет свой таймер, событие и подсветку; краткое моргание не должно сбрасывать удержание, устойчивое возвращение к CENTER сбрасывает.
7. **«Кейс №3»** показывает все пункты PDF, в том числе неактивную защиту. В exam пользователь не может менять диагностические пороги; повторная принятая калибровка требует пароль экзаменатора.
8. «Завершить и сохранить» освобождает камеру/потоки. События, скриншоты (если включены), calibration, timings и runtime JSON лежат в `data/sessions/<run>/`. Данные остаются локальными; для учебных заведений нужны правила согласия/доступа/срока хранения.

## Что исправлено

- CV доступен сразу, без обязательного прохождения интерфейса экзамена. Нет gates по ФИО, числу мониторов, запуску страницы теста или успешности всех пяти поз.
- Поиск телефона: глобальная nano-YOLO на более детальном входе + дозированный ROI-поиск маленьких/слабых объектов. Пока телефона нет — перекрывающиеся квадранты; при кандидате — его окрестность. Дубликаты объединяются до tracker. Уверенный крупный phone не вызывает лишнее уточнение. Слабое текущее наблюдение может поддержать подтверждение до 0.8с после strong; прогноз без наблюдения — никогда.
- Adaptive больше не опускает обычный поиск телефона до 320 в новом профиле; нижняя граница 416. Частота всё ещё адаптируется по измеренному времени, старые кадры отбрасываются.
- Первичное лицо: FaceMesh в расширенной ROI. Остальной кадр независимо проверяется FaceDetection в 5 Hz для присутствия и второго лица. ROI не скрывает второго человека.
- Iris проецируется в локальный 3D-базис головы/собственного глаза по относительной глубине MediaPipe; это уменьшает влияние поворота головы, но не означает измерение метрического 3D-взгляда. Вертикаль нормализована шириной глаза, не скачущей высотой раскрытия века. Вертикальное значение может быть отрицательным: это координата, не вероятность. Убрано клиппирование, которое съедало направление UP.
- Пять поз обучают пороги по различимому диапазону движения и шуму центральной позы: малое, но устойчивое отклонение не теряется из-за фиксированного порога. Неразличимые позы не выдаются за обученные.
- Раздельные per-eye EMA/центры, более мягкий blink gate, коррекция сравнения глаз по вертикали. Head pose остаётся отдельным PnP-состоянием, не заменяет Eye Gaze.
- Все пять направлений показаны отдельными активными индикаторами для HEAD и GAZE. Настройки/диагностика убраны с основного экрана во вкладку. Фактические yaw/pitch/roll, отклонения глаз, пороги входа и причины UNKNOWN видны рядом.
- Убраны фиктивные нули/«accuracy %» и произвольный trust-score из основного CV-экрана. FPS/Hz — реальные обработанные кадры, не target_fps. Возраст данных определяет их пригодность для правил. Ошибка модели не выдаётся за отсутствие ученика.
- Каждый пункт PDF имеет живую строку статуса. Неподдерживаемая/выключенная защита не окрашивается как успешно работающая.

## Защита окружения — отдельно от просмотра CV

Обычный `dev` не блокирует компьютер оператора. На Windows с правами администратора:

```bash
python -m proctor.tools.set_password
python -m proctor.main --profile exam
```

В этом режиме включены keyboard hooks, clipboard guard, focus watchdog и наблюдение запрещённых новых процессов; окно закрывается по паролю через **Ctrl+Shift+F12**. `--demo/--no-guard/--video/--run-seconds` для exam запрещены. Для автономного CV режима URL теста не требуется.

**Защита вкладок** возможна только внутри управляемого браузера. Если действительно нужен браузер, задать **реальный** `test.test_url`, затем:

```bash
python -m proctor.main --embedded-test --profile exam
```

Нет автоматической страницы с вопросами: при пустом URL режим браузера отказывает с понятным сообщением. Встроенный браузер не открывает дополнительные окна, не разрешает чужие hosts/произвольные local files и блокирует навигацию до загрузки. На Linux/macOS полная блокировка Windows-клавиш/чужих окон не заявляется.

Реализация не является доказательством точности. Чтобы подтвердить все LEFT/RIGHT/UP/DOWN, телефон в разных руках/чехлах/свете и второго человека, нужны реальные размеченные видео с целевой камеры. «Наведение камеры телефона» всё ещё **эвристика положения+удержания**, не распознавание ориентации объектива. Webcam-драйвер может блокировать native read; stale detector не равен гарантированному принудительному перезапуску драйвера. Существующие программы/привилегированные OS shortcuts не закрываются полностью application-level MVP.

Старый [CV_AUDIT.md](docs/CV_AUDIT.md) и benchmark JSON относятся к предыдущей реализации. Не использовать их FPS/число unit-tests как доказательство качества этой ревизии. Отдельные технические smoke-проверки тоже не заменяют камеры/телефона/Windows.
