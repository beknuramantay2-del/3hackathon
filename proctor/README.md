# Кейс №3 — локальный школьный MVP и CV-прокторинг

Теперь доступны **локальные роли, регистрация, собственные тесты, попытки/ответы, кабинет экзаменатора и футаж**. Запуск школьного клиента после установки:

```bash
python -m proctor.school
# только для проверки без OS-защиты:
python -m proctor.school --preview
```

Первого администратора создаёт оператор; дефолтных аккаунтов/вопросов нет. Ученик → свой тест → согласие/preflight → обязательные 30 с головы/глаз → ответы. Привилегированный кабинет и кнопка «Экзаменатор» доступны по проверенной роли/паролю. [SCHOOL_SYSTEM.md](docs/SCHOOL_SYSTEM.md) — полная инструкция, роли, база, запуск и реальные ограничения.

`python -m proctor.main` по-прежнему открывает большой операторский CV-экран. **Полная приёмка Case 3 ещё не пройдена:** регистрация и интерфейс не заменяют доказанную точность детектора и Windows-защиту.

## Установка и запуск

Python 3.10–3.11, из корня репозитория:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r proctor/requirements.txt
python -m proctor.tools.fetch_weights
python -m proctor.main
```

На Linux Qt может требовать mesa/libGL/libEGL и libxkbcommon-x11. Установить зависимости и веса заранее; offline-режим не скачивает модели во время экзамена и не подменяет ошибку mock-детектами.

Слабое устройство: `python -m proctor.main --perf weak`.
Локальный replay: `python -m proctor.main --video video.mp4` — явно видео, не физическая камера.

## Настройка и сигналы

1. После загрузки моделей начинается **обязательная настройка 30 с**: 5 положений головы (15 с), затем 5 направлений глаз (15 с) с прямой головой. Подсказка/точка/звук ведут по шагам.
2. Все направления должны быть различимы. Статичные, нечитабельные или неполные данные не принимаются; при ошибке повторить одной кнопкой. Обход «центр 2 с» удалён. До принятия HEAD/GAZE — UNKNOWN, не ложные CENTER/LEFT/DOWN.
3. Камера показывает весь кадр без обрезки, около половины площади приложения. Две основные кнопки: настройка и завершение. Под камерой отдельные HEAD/GAZE, в кадре — лица, руки, телефон и стрелки читаемых глаз.
4. **Телефон: красный сигнал на первом надёжном результате**, без дополнительного hold. Слабый кандидат требует подтверждения; прогноз/старый кадр не предупреждают. «Первый результат» не означает физические 0 ms. Confidence не является точностью в процентах.
5. **Голова/глаза в любую сторону, включая вниз:** с начала сохраняется эпизод; <3 с без предупреждения, ≥3 с жёлтый, ≥5 с красный. Короткий шум переживается, устойчивый CENTER сбрасывает. Красный — запрос ручной проверки, не доказательство списывания.
6. Двойной клик по событию открывает готовый локальный футаж. Фрагмент, который ещё записывается, будет доступен после завершения. В exam просмотр по паролю экзаменатора.
7. «Настройки»: реальные yaw/pitch/roll, per-eye координаты, quality/UNKNOWN, применённые пороги, ROI, FPS/Hz, возраст данных, время стадий, CPU/RAM и ошибки записи. Жёлтый/красный пороги 3/5 с реально управляют сигналами; в exam изменение заблокировано.
8. Штатно завершить и проверить `data/sessions/<run>/`: `session.db`, `shots`, `clips` AVI/JSON, calibration/timings/runtime. Футаж — 480×360/5 fps, до 2 с до/после, сегменты по 15 с, без аудио/экрана. SQLite/encoding вынесены из Qt в bounded workers.

## Что исправлено в CV

- Неполная настройка больше не выдаётся за готовность. Голова и глаза обучаются отдельно.
- Персональные head-пороги не перекрываются фиксированными 18°/12° без явного операторского override.
- Head rotation — face-local 3D basis по относительной глубине MediaPipe, с геометрическими gates; gaze — отдельные iris/центры обоих глаз и EMA. Метрическая 3D-точность не заявляется. Нечитаемые/несогласованные глаза — UNKNOWN, не направление.
- Единая episode policy live и embedded, без повторного cooldown, скрывающего повышение жёлтого до красного. Краткие отводы, подъём/рука и системные сигналы имеют эпизоды и связь с футажом.
- Ранее добавленный nano-YOLO global/ROI, tracker, hand/time и свежесть сохранены; одновременно максимум один global + один дозированный detail. Новая запись не добавляет тяжёлый CV-detector.
- Последние 178 локальных тестов прошли, включая native YOLO/MediaPipe/Hands/WebEngine smoke и настоящий MJPG-кодек. Это не доказательство precision/recall на реальных учениках.

## Защищённый экзамен

Обычный dev — экран оператора, компьютер не блокируется. Для Windows/admin:

```bash
python -m proctor.tools.set_password
python -m proctor.main --profile exam
```

Включаются keyboard/clipboard/focus/process guards; выход Ctrl+Shift+F12 по паролю. В exam запрещены video/demo/no-guard/run-seconds. Это application-level MVP, **не полноценный OS kiosk**.

Запрет браузерных вкладок возможен только в управляемом браузере: задать реальный `test.test_url`, затем:

```bash
python -m proctor.main --embedded-test --profile exam
```

Страница-заглушка автоматически не подставляется. Перед открытием — preflight и полная калибровка. При её потере ввод ответов заблокирован; нужен экзаменатор/новая сессия. Таймер стороннего сайта этим не приостанавливается. Старый HTML-отчёт/HTTP-monitor могут содержать эвристический trust-index: **не accuracy, не оценка учащегося и не основание автоматического решения**. Новая главная UI его не использует.

## Приёмка и следующий этап

- [CV_CALIBRATION_EPISODES.md](docs/CV_CALIBRATION_EPISODES.md) — текущая логика, БД, инструкция оператору и план ролей/тестов/админского кабинета.
- [CASE3_ACCEPTANCE.md](docs/CASE3_ACCEPTANCE.md) — каждый пункт PDF, что технически сделано и что реально не принято.
- [Native measurements](docs/benchmarks/mandatory-cv-native.json) — статичный replay в Linux sandbox, не обещание FPS на слабом Windows-ноутбуке.

**Не закрыто по реальному качеству:** телефон едва над столом, естественные L/R/U/D глаз/головы на целевой камере, два живых человека/плохой свет, физическое подавление Windows shortcut/windows. PHONE_AIMED — эвристика положения, не достоверное распознавание ориентации объектива/намерения фотографировать. В default CV нет браузера, поэтому «все пункты Case 3 закрыты» неверно.

Локальный school-клиент с roles/users/tests/attempts, собственными вопросами/ответами и просмотром эпизодов теперь реализован. Это один клиент/одна активная попытка, не сетевой мониторинг класса; архивный UI пока ограничен последними 200 попытками/100 эпизодами. Перед школьным использованием нужны реальная CV/Windows-приёмка, согласие, права доступа и сроки удаления. Native E2E проверяет проводку ответов с **явным calibration/monitor stub**, не физические движения человека.
