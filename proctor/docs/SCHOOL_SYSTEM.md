# Панель наблюдения

Администратор и экзаменатор видят только наблюдение: учеников, текущие и завершённые сессии, состояния камеры, события и футаж. Создание тестов и управление аккаунтами вынесены в отдельную подготовку, не в панель.

## Подключение

```powershell
python -m proctor.school --monitor
python -m proctor.school --student --preview --perf weak
```

Это два отдельных процесса на одном компьютере. Для проверки запустите их в разных терминалах, войдите в разные роли, начните ученический тест и выберите эту сессию в панели. Панель читает ту же `data/school.db` и актуальный снимок из каталога конкретной попытки; камера и модели загружаются только в ученическом CV-процессе.

Если используются `--db`, путь должен быть одинаковым и абсолютным. Не размещайте SQLite на сетевом диске. Есть отдельные блокировки клиента и панели; одновременно возможен один ученический экзамен и одна отдельная панель. Это не LAN-сервис для параллельного класса.

Кадр передаётся до 2 Гц, не более 480×360, фоновым worker с одним pending-слотом. JPEG и состояния находятся в одном атомарно заменяемом файле, поэтому при чтении не смешиваются разные версии снимка панели. CV работает асинхронно: последнее измерение может относиться к более раннему кадру, чем текущий preview; quality/freshness gates остаются в pipeline. В карточке указан возраст изображения. После 3 с без нового кадра показано отсутствие связи, а завершённая попытка не считается live.

Ученик не может читать панель через сервис: роль проверяется при каждом чтении кадров/записей. После истечения сессии панель возвращается к входу. Права приложения не заменяют права ОС на файлы.

## Подготовка

Команды `python -m proctor.school.manage init`, `account` и `import-test` описаны в [README](../../README.md). Пароли запрашиваются скрыто. Преподаватель импортирует свои вопросы; готовые демонстрационные тесты не создаются автоматически. Правильные ответы остаются в SQLite, не в HTML ученика.

## Во время экзамена

Обязательная настройка — 15 с головы и 15 с глаз. До успешного завершения вопросы недоступны. Направления во время настройки могут быть показаны предварительно, без тревог. Ученик видит отдельные HEAD/GAZE и техническое состояние; пороги, подробный журнал и чужие записи ему не открываются.

Выберите сессию в панели. Таблица показывает имя, тест, статус, баллы, источник и уровни событий. Откройте журнал для длительностей и готового футажа. Жёлтый/красный — запрос ручной проверки, не автоматическое обвинение. Повышение одного эпизода до красного не создаёт второй эпизод.

В отдельной панели кадр live только пока он свежий. В журнале завершённой сессии может быть показан сохранённый снимок события — он явно помечен, не выдаётся за текущую камеру. Внешних email/push-уведомлений нет; в открытом журнале новые уровни сопровождаются локальным звуком.

На защищённом Windows-сеансе переключение на другую программу должно фиксироваться. Поэтому не переводите фокус на отдельную панель из ученического экзамена. Для локального вмешательства используйте парольный кабинет «Экзаменатор» внутри сеанса или штатный выход Ctrl+Shift+F12. Preview годится для совместной проверки двух окон, но не защищает экзамен.

## Сбой и завершение

При отправке проверяются реальные ответы, баллы — правильные ответы / число вопросов. При сбое не выдумывается успешное завершение. Закрывайте зависшую попытку в панели только после фактической остановки дочернего процесса. Изменение статуса базы само по себе не убивает процесс; клиент проверяет статус с интервалом до 2 с.

После остановки writers итоговый журнал связывается с attempt ID и архивируется в общей базе. AVI остаются файлами, не BLOB. Панель показывает последние 200 попыток и 100 эпизодов; это ограничение отображения, а не удаления данных.

## Хранение и ограничения

Общая SQLite: аккаунты, тесты, ответы, попытки, итоговые evidence. Per-run SQLite, снимки, sampled AVI/JSON, калибровка и метрики — в `data/sessions`. Нет аудио, записи экрана, облачной отправки и биометрической проверки личности. Нужны согласие, права ОС, срок удаления и резервные копии.

Проверены межпроцессный обмен кадром/состояниями, роли, stale/повреждённые данные, отдельные locks и native путь HTML → WebChannel → ответы → SQLite с тестовой калибровкой. Это не доказывает точность CV и физическую защиту Windows. [Оставшиеся требования](CASE3_ACCEPTANCE.md).
