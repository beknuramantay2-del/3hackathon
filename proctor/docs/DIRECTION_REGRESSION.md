# Исправление регрессии головы и взгляда

## Причины

- После ввода обязательной полной калибровки controllers перезаписывали HEAD/GAZE в UNKNOWN, а UI повторно скрывал предварительные состояния и стрелки.
- Ученический экран полностью скрывал карточки состояний; подпись DirectionReadout не была включена в layout.
- Backend головы изменился с PnP на относительный mesh-базис. Восстановлен прежний PnP SQPnP+LM с проверкой геометрии/reprojection и персональным центром; автоматического смешивания двух геометрий нет.
- Строгое требование обоих глаз скрывало даже читаемый одиночный глаз. Это требование сохранено для предупреждений, но не для явно помеченного preview.

## Что теперь видно

- HEAD и GAZE независимы, CENTER/LEFT/RIGHT/UP/DOWN. Карточки доступны оператору и ученику; на шаге настройки также показаны измеренные направления.
- Стрелки головы и читаемых глаз соответствуют текущему измерению и зеркальному отображению кадра.
- Стабильный центр обучается только по размеченному шагу «Прямо» (минимум 8 стабильных измерений), а не по произвольной неподвижной позе. До измеренного центра — UNKNOWN.
- До полной настройки направление подписано «Предварительно · без предупреждений». Если один глаз читается, возможен только preview; gaze-тревога требует двух согласованных читаемых глаз.
- Успешно измеренные голова/центр не исчезают только из-за последующей ошибки глазного прохода. Смена основного лица аннулирует настройки, устаревшее измерение не рисует выдуманное направление.

## Что не ослаблено

Обязательные 15 с головы + 15 с глаз и различимость всех направлений остаются. Неполная настройка не открывает вопросы. Предварительные направления не создают направленных условий, эпизодов или жёлтых/красных тревог. После принятия полной настройки действуют прежние длительности 3/5 с и quality/freshness gates. Телефон и OS-защита этим фикс-пакетом не переобучены и не объявлены точными.

## Проверка

**193 теста прошли** с native YOLO/MediaPipe/Hands/WebEngine/school smoke. Новые регрессии проверяют четыре направления головы и глаз по отдельности, отсутствие тревог от preview, monocular preview без gaze warning, потерю/смену лица, сохранение head preview после ошибки глаз, стрелки overlay и layout подписи. Значения движения в этих тестах синтетические, не ground truth живого ученика.

20-секундный native прогон статичного публичного face replay показал измеренный нейтральный preview CENTER для головы/глаз и метод PnP SQPnP+LM. Направленная калибровка закономерно не принята: портрет не поворачивается. Эпизодов/роликов/ошибок evidence — 0. [Измерения](benchmarks/direction-regression-native.json). Это проверка проводки модели → правила → UI, не доказательство того, куда действительно смотрит человек на портрете.

Средний preview age ~16.8 ms; PnP ~1.31 ms, eye-gaze ~0.33 ms, UI ~1.73 ms. Это ограниченные rolling windows Linux sandbox; preview age не равен latency тревоги, цифры не обещают FPS целевого ноутбука. YOLO (~108 ms с detail) остаётся главным вычислительным узким местом. Нового тяжёлого детектора/очереди кадров нет.

Физическая камера пользователя, естественные движения L/R/U/D, очки/плохой свет, Windows-блокировки и визуальная QA на целевом DPI не проверены. **Полная приёмка Case 3 не объявляется закрытой.**

## После обновления

1. `git pull`, остановить старый процесс и перезапустить приложение.
2. Пройти калибровку заново: backend головы изменился, старые персональные параметры нельзя считать подходящими.
3. Следовать отдельно подсказкам головы и глаз; не двигать голову в глазном проходе. Сначала проверить голову CENTER + глаза L/R/U/D, затем только повороты головы.
4. При UNKNOWN смотреть конкретную причину читаемости/настройки, а не снижать quality gates ради зелёного статуса. При ошибке позы повторить настройку, проверить свет/блики/положение камеры.
