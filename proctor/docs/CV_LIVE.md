# CV без страницы теста — архитектура и границы

Актуальные изменения для учебных заведений: [SCHOOL_MVP.md](SCHOOL_MVP.md). Live-калибровка теперь запускается явно кнопкой (10 с / центр 2 с), не автоматически.

## Почему предыдущая версия не была достаточной

1. В `main` оставался исходный код: предыдущие изменения были только в draft PR.
2. Интерфейс/правила для пользователя фактически появлялись лишь после preflight, полной калибровки и загрузки страницы теста. Поэтому визуально «ничего не считывается» даже при работающих потоках.
3. Уменьшение YOLO до 320, три подтверждения и скрытые слабые candidates ухудшали ощущение/recall маленьких телефонов. Нужна детализация, а не новое число FPS.
4. Высота раскрытия века использовалась как denominator вертикального взгляда: DOWN/UP и моргание искажали само измерение. Жёсткий blink gate отбрасывал полуприкрытый глаз при взгляде вниз.
5. Абсолютная вертикальная разница между глазами считалась ошибкой, хотя у человека могут быть разные нейтральные позиции глаз. Переключение на один глаз с общим центром создавало ложное отклонение.
6. После смены системы нормализации клиппирование V в 0..1 съедало настоящий UP. Исправлено: V — подписанная координата в локальной системе, допустимы отрицательные значения.
7. В интерфейсе показывались target Hz вместо фактической частоты и default-zero вместо неизвестной геометрии. Эти значения не являлись проверкой детекции.

## Реальный pipeline

Camera → latest slot → nano-YOLO(global + gated detail ROI)/tracker + face scan(full frame, 5Hz)/FaceMesh(primary ROI)/iris + gated Hands → fresh-only independent HEAD/GAZE → hold/hysteresis/cooldown → SQLite события → live UI.

FaceDetector и FaceMesh локальные, их модели поставляются MediaPipe. Nano-YOLO COCO считает person/cell phone, **не face**. Веса не менялись на несуществующие «обученные под кейс»: улучшено разрешение/покрытие/логика, без обещания нового training accuracy.

## Роль чисел — без декоративного score

| Значение | Откуда берётся | На что влияет |
|---|---|---|
| Phone confidence / порог | YOLO и регулятор пользователя | Создание/сильное подтверждение track, phone_voted, PHONE_* holds. Weak recovery разрешён только по текущему наблюдению и strong anchor не старше 0.8с; дополнительная weak-support ветка требует руки+времени или согласия global/ROI+времени; повышенный порог сбрасывает старые подтверждения. Не является долей правильных ответов модели |
| Candidate / confirmed | NMS и tracker подтверждения | Слабый кандидат рисуется, но не даёт доказательства phone warning |
| HEAD Δ yaw/pitch | PnP и принятый центр | Независимая классификация HEAD по реальным входным порогам; roll не подменяет yaw |
| Eye L/R H/V | Iris собственного глаза, head-local 3D axes (относительная глубина MediaPipe) | Per-eye smoothing и персональный центр; один глаз не сравнивается с общим абсолютным нулём |
| GAZE Δ H/V и L/R/U/D gates | Относительные измерения и calibration targets | Классификация GAZE; показаны actual entry gates, exit hysteresis = 70% |
| Удержание X/Y секунд | monotonic HoldRule | До Y нет warning, после Y — событие с сохранённым duration; стабильный CENTER сбрасывает |
| Camera FPS / worker Hz | Реально доставленные/обработанные frames | Диагностика throughput; не подменяются target_fps |
| Возраст результатов | now − captured_at | Истёкшие результаты не участвуют в правилах; UNKNOWN вместо старого HEAD/PHONE |
| Пропущенные frames | Разница sequence IDs | Доказывает latest-frame skipping, не «потерю всех детектов»; backlog не догоняется |
| Imgsize / processing EWMA | Фактический размер/стоимость inference | Adaptive rate; нижняя граница phone поиска выше старого 320 |
| Очередь записи / ошибка | bounded writer | Показывает несохранённые операции, а не поддельное «нарушений нет» |

Нет фиктивного 100% качества, количества «успешно закрытых пунктов» или нового trust-score. При отсутствии валидных данных численные измерения заменяются UNKNOWN/«—» с причиной.

## Калибровка и интерпретация

- Центр по кнопке: после готовности лица — точка/звук/2 секунды. Пользователь должен смотреть прямо; это не автоматическое угадывание истинного нейтрального направления.
- Повторить центр после изменения позы/дистанции/положения камеры. При ошибке/недостатке sample калибровка не объявляется успешной.
- Быстрая live-калибровка за 10 секунд двигает цель во всех пяти направлениях. Тримминг, переходные кадры и индивидуальные eye centres остаются частью рабочей логики.
- При различимых противоположных позах входные пороги учитывают меньший продемонстрированный диапазон и MAD центральной позы. У малого отклонения нет обязательного завышенного фиксированного порога; шум/неразличимые позы явно отклоняются.
- 3D-базис использует относительную глубину landmarks, не метрическую калибровку камеры. Геометрическая проверка при повороте базиса не доказывает точность MediaPipe при реальном сильном повороте.
- HEAD/GAZE warnings не запускаются до принятого центра. Телефон/присутствие не скрываются за необходимостью открыть страницу теста.
- Пока глаза нечитаемы, состояние UNKNOWN, а не «точный CENTER». Порог можно подобрать по реальным отклонениям, но нельзя настроить вероятность точности «цифрой %».

## Что действительно проверено в среде разработки

- Python 3.11 compile и запуск default `proctor.main` без браузерной страницы.
- Нативный ROI FaceMesh/FaceDetection: публичное статическое изображение лица даёт наличие лица, валидный PnP и измерения обоих глаз. Это **не разметка направлений**.
- Проверена геометрическая инвариантность нейтрального iris при синтетическом вращении head-local базиса. Это не видео с размеченным взглядом.
- Нативный nano-YOLO global+detail в пустой сцене: не выдаёт подтверждённый phone. Это **не положительная проверка реального телефона**.
- Регулятор phone confidence изменён в живом приложении с .25 на .40; фактический detector threshold и runtime JSON принимают .40, оба worker продолжают обрабатывать новые sequence IDs.
- Runtime сохраняет HEAD/GAZE, source, калибровку, фактические frame counts и 17 живых case-status rows. Входной видео-source не выдаётся за физическую камеру.
- Завершение освобождает потоки/SQLite. Кнопка auto-stop разрешена только в dev, не обходит exam lock.

**Не утверждается:** все физические 19 сценариев уже пройдены, телефон детектируется при любом освещении/размере, взгляд всегда точен или Windows/GPU проверены. Нужны записи пользователя/целевое устройство. Не подменять это количеством unit-tests или FPS из прошлой ревизии.

## Следующий шаг для подтверждения качества, а не интерфейса

Взять реальную запись: прямо → только глаза L/R/U/D → только голову L/R/U/D → комбинации → phone in hand/near screen/lift/remove → второй человек → уход → плохой свет. По кадрам/времени сверить states и events с действиями; затем настроить персональные thresholds/confidence или подготовить собственные phone weights. Без таких данных честно закрывается реализация/наблюдаемость, но не заявляется приёмка качества всего Кейс №3.
