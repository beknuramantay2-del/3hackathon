Последний фикс: [DIRECTION_REGRESSION.md](DIRECTION_REGRESSION.md); основание CV: [CV_CALIBRATION_EPISODES.md](CV_CALIBRATION_EPISODES.md). **Обязательная настройка 30 с, 3/5 с сигналы, SQLite всех эпизодов и локальный футаж. ## UI — не просто увеличенный пустой QLabel

На 1280×800, источник 640×480: **видимое изображение 842×632, 52% площади окна**. Раньше та же фотография занимала примерно 400×300 внутри широкой, но низкой камеры. Теперь убраны высокие карточки, повторные ряды из пяти стрелок, отдельная строка кнопок и второстепенные подписи над видео. Две основные кнопки: «Настроить голову и глаза · 30 с» / «Завершить и сохранить». Обновление только центра удалено: оно не заменяет обязательные два прохода.

Кадр сохраняет соотношение сторон целиком. Растяжение/обрезка/zoom-to-fill не используется — иначе телефон у нижнего края мог бы пропасть только из интерфейса. При изменении окна масштабируется исходный cached pixmap, а не уже уменьшенная картинка; не нужно ждать новый кадр. HUD не закрывает нижнюю полосу: HEAD/GAZE находятся сразу под видео, а eye/phone/face overlays остаются на своих координатах в изображении. Фактический image_size сохраняется в runtime, рядом с window_size.

Qt отрендерил основной экран / требования / настройки, проверки площади кадра и двух видимых основных кнопок прошли. Просмотр PNG через инструмент недоступен: **визуальная QA не объявляется пройденной**. Нужна проверка на целевом Windows/DPI.

## Детектор — что изменено, без обещания невидимых признаков

- Вместо поиска только крупными квадрантами, неизвестный телефон сначала ищется в трёх перекрывающихся нижних ROI: центр / слева / справа, затем общий квадрант. Нижние ROI покрывают всю ширину и доходят до последней строки кадра. Точка начала нижней полосы — 55% высоты.
- Если есть текущий модельный кандидат либо кандидат прошлого снимка ≤0.65 с, поиск фокусируется около него. Старые кандидаты не удерживают ROI навсегда. Для очень слабого маленького фрагмента — более тесный zoom; для остальных сохранён более широкий контекст, чтобы не ухудшить прежнюю детекцию руки/телефона.
- Бюджет не вырос до многих проходов: максимум **один global + один detail** на обработанный кадр, detail — на каждом втором цикле и только при необходимости. Другие зоны не исключены: global всегда видит весь кадр; квадранты остаются в ROI-расписании.
- В диагностике показаны действительно применённые ROI, размер входа и число detail inference. Confidence не повышается искусственно. Tracker/hand+time/global+ROI+time требуют реальных наблюдений, прогноз не создаёт phone warning.

## Оптимизация и проверка — без фиктивного FPS

Latest-only transport, отдельные workers, bounded SQLite writer, свежесть данных, прежняя частота/потоки/адаптивный бюджет сохранены. Большая картинка влияет на preview, не повышает imgsz всех моделей. При resize используется один исходный pixmap, HEAD/GAZE не создают десятки обновлений стилей стрелок. Дополнительного тяжёлого детектора нет.

Проверены технические регрессии, area/aspect-fit, отсутствие старых ROI, лимит двух inference, отсутствие warning из пустого desk, краткого шума, stale и predicted-only данных. Эти проверки **не являются доказательством точности в реальной школе**.

Для следующей приёмки: реальный URL страницы экзамена + Windows-прогон защиты, короткое локальное видео с видимым/наполовину закрытым/едва видимым телефоном за столом, отдельные только-глаза / только-голова L/R/U/D, уход и второй человек. До этого не публиковать «все пункты Кейс №3 закрыты».

## Проверки этой ревизии

- 193 локальных теста прошли с включёнными native smoke: 3 настоящих YOLO/MediaPipe/Hands проверки + WebEngine; остальные — технические регрессии, не accuracy dataset.
- Нативный 20-секундный прогон статичного public face replay **не прошёл направленную калибровку**, как и должен: полный экзамен не квалифицирован, показан нейтральный HEAD/GAZE CENTER относительно измеренного центра с пометкой preview, нет выдуманных эпизодов/роликов. Это не ground truth направления глаз портрета. [direction-regression-native.json](benchmarks/direction-regression-native.json).
- Реальный MJPG-кодек в тесте создал AVI, pre-roll, SQLite-связь и SHA256; это синтетические кадры, не учащийся.
- [mandatory-cv-native.json](benchmarks/mandatory-cv-native.json): последние ограниченные rolling windows, не замеры пользовательского ноутбука. Preview age mean ~17.1 ms, p95 ~31.1 ms; YOLO global+detail mean ~109 ms, p95 ~186 ms. **Главный вычислительный bottleneck — YOLO/ROI, не новая temporal logic (~0.1 ms).** Preview age не равен latency предупреждения/качеству CV.
- Визуальный просмотр PNG недоступен: layout/native Qt тесты прошли, но визуальная QA на Windows/DPI остаётся.

Ни количество тестов, ни модельный smoke, ни работающий AVI **не закрывают оставшиеся реальные сценарии PDF**. Телефон за столом, глаза/голова пользователя, второй живой человек, плохой свет и физические Windows-блокировки требуют отдельной приёмки.

## Школьный workflow

Собственный school-клиент теперь связывает аккаунт/тест/attempt ID с обязательной калибровкой, защищаемым WebEngine, ответами/реальными баллами и SQLite evidence. Ученику показываются отдельные статусы головы и взгляда; технические пороги/лента нарушений скрыты. Экзаменатору — парольный просмотр текущей попытки и роли/имена/история/эпизоды/готовый футаж. Native round-trip HTML→WebChannel→SQLite прошёл с явно synthetic calibration/monitor fixture; это **не новая CV-accuracy или физическая Windows-приёмка**.

Нет дефолтного теста/пароля, нет сетевого наблюдения за классом, нет точного распознавания ориентации камеры телефона. Цель PDF «одновременно точный CV и защищённое тестирование» по-прежнему требует целевой камеры/Windows и живых сценариев.
