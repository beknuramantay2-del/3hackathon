# Локальный прокторинг

Приложение для наблюдения за учеником во время теста. Камера, распознавание, аккаунты, события и видеозаписи работают локально. Интернет нужен для первоначальной установки зависимостей и моделей, но не для экзамена.

Голова и взгляд измеряются отдельно. В кадре подсвечиваются лица, глаза, руки и найденный телефон. Экзаменатор видит имена учеников, состояние сессии, свежий кадр, предупреждения и сохранённые фрагменты. Сигналы помогают проверить ситуацию, но не выносят автоматическое решение о нарушении.

## Установка

Нужен Python **3.10 или 3.11**. Откройте терминал в корне проекта.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r proctor/requirements.txt
python -m proctor.tools.fetch_weights
```

На Linux активируйте окружение командой `source .venv/bin/activate`. Для Qt нужны системные библиотеки GL/EGL, XKB, NSS и XKBFile. На Windows защищённый режим требует прав администратора. Если PowerShell запрещает активацию, запускайте команды через `.venv\Scripts\python.exe` без изменения системной политики.

## Первоначальная подготовка

Админ-панель предназначена **только для наблюдения**: редактора вопросов и кнопок создания тестов в ней нет. Аккаунты и вопросы подготавливаются отдельно. Пароли вводятся в терминале скрыто; не передавайте их в командной строке.

```powershell
python -m proctor.school.manage init --login teacher --name "Преподаватель"
python -m proctor.school.manage account --login teacher --new-login student01 --name "Имя ученика"
python -m proctor.school.manage import-test --login teacher questions.json
```

`questions.json` — файл преподавателя в UTF-8. Например:

```json
{
  "title": "Название теста",
  "minutes": 20,
  "questions": [
    {"text": "Текст вопроса", "options": ["Ответ A", "Ответ B"], "correct": 1}
  ]
}
```

Индекс `correct` начинается с нуля. Этот пример не добавляется в базу автоматически. Дефолтных паролей, учеников и тестов нет.

## Панель и приложение ученика

В первом терминале:

```powershell
python -m proctor.school --monitor
```

Войдите как администратор или экзаменатор. Панель показывает наблюдение, список учеников и краткую инструкцию. Выберите сессию, чтобы видеть кадр и состояния; кнопка «Открыть события и футаж» открывает журнал и готовые записи.

Во втором терминале на **том же компьютере**:

```powershell
python -m proctor.school --student --preview --perf weak
```

Войдите как ученик. Выберите подготовленный тест, подтвердите локальную запись и пройдите калибровку. **`--preview` отключает защиту рабочего окружения**; этот режим нужен для проверки подключения и камеры, а не для защищённого экзамена.

Оба процесса используют `data/school.db`. Панель не запускает YOLO/MediaPipe и не захватывает камеру повторно. Разные locks позволяют открыть панель и клиент одновременно, но не два ученических клиента. Поддерживается одна активная попытка на компьютере, история остальных учеников сохраняется.

Если база находится в другом месте, в обеих командах и командах подготовки укажите одинаковый абсолютный путь: `--db "C:\ProctorData\school.db"`. **SQLite должна находиться на локальном диске**, не на сетевой папке или в синхронизируемом облачном каталоге. Это не сетевой сервер для класса на разных компьютерах.

## Защищённый запуск

На Windows запустите терминал с правами администратора:

```powershell
python -m proctor.school --student --perf weak
```

Здесь нет `--preview`. Включаются доступные keyboard/clipboard/focus/process guards и ограничения управляемого браузера. Во время защищённого экзамена **не переключайте фокус на отдельную панель**: такое переключение должно фиксироваться. Для проверки записи из ученического сеанса предусмотрен парольный кабинет экзаменатора. Ctrl+Shift+F12 — выход по паролю.

Защита прикладная, не полноценный системный kiosk: все комбинации клавиш, внешние окна и обходы Windows нужно проверить на целевом компьютере. На Linux/macOS защищённый школьный запуск не допускается.

## Калибровка и сигналы

- **30 секунд:** пять положений головы, затем пять направлений глаз с прямой головой. Неполная настройка не открывает вопросы.
- После измерения центра направления видны с пометкой «Предварительно». Эти значения не создают направленных тревог. Нечитаемые глаза или потеря лица отображаются как неизмеренные данные, а не как выдуманное направление.
- Телефон: первый надёжный модельный результат — красный сигнал. Слабому кандидату требуется подтверждение; это не обещание обнаружения с первой миллисекунды.
- Голова/взгляд в сторону, включая вниз: до 3 с — запись без тревоги, с 3 с — жёлтый, с 5 с — красный. Возврат в центр сбрасывает удержание; короткий шум не создаёт отдельный шторм событий.
- Свежий кадр панели обновляется до 2 раз в секунду, данные опрашиваются раз в секунду. После 3 с без свежего кадра изображение убирается и показывается ошибка связи. Остановленная сессия не выдаётся за live.
- Футаж сохраняется отдельно: sampled camera video 480×360, 5 FPS, до 2 с до и после события. Аудио и рабочий стол не записываются.

## Производительность

YOLO nano, latest-frame workers, ограниченные очереди, дозированный ROI-поиск, адаптивная частота моделей и отдельная запись SQLite/видео. Отставший обработчик берёт свежий кадр, а не разгребает старую очередь. Увеличение камеры в интерфейсе не увеличивает вход каждой модели. Панель получает маленький JPEG от фонового worker, а не запускает вторую копию CV.

`--perf auto` выбирает профиль по доступным ресурсам; `--perf weak` снижает нагрузку, `--perf balanced` задаёт более высокий бюджет. Эти профили не заменяют проверку точности и задержки на конкретном ноутбуке.

Целевая слабая конфигурация: **Intel Core i5‑4200M 2.50 GHz, 8 ГБ RAM, Windows x64**. Для неё предусмотрен `weak`. Подтверждённого замера запуска/FPS на этой машине в проекте нет — характеристики компьютера сами по себе не являются результатом тестирования.

В опубликованном Linux replay-прогоне средний возраст preview был около 16.8 ms, PnP головы — 1.31 ms, вычисление взгляда — 0.33 ms, YOLO с detail — около 108 ms. Это замеры конкретного статичного replay, **не latency тревоги и не результат i5‑4200M**. Исходные данные: [измерения](proctor/docs/benchmarks/direction-regression-native.json).

## Данные

`data/school.db` — аккаунты, тесты, попытки, ответы и итоговый архив. `data/sessions/<session>/` — журнал CV, снимки, AVI/metadata и последний кадр наблюдения. Последний кадр ограничен по размеру, заменяется атомарно и доступен в приложении только привилегированной роли.

Пароли хешируются PBKDF2; правильные ответы не передаются в ученический HTML. При этом роль приложения не защищает файлы от владельца той же учётной записи ОС. До использования с учениками настройте права ОС, согласие на запись, срок хранения и резервное копирование.

## Проверка проекта

```powershell
pip install -r proctor/requirements-dev.txt
python -m compileall -q proctor
python -m pytest -q proctor/tests
```

Последний полный запуск: **201 тест прошёл**, включая native проверки моделей, WebEngine и школьного workflow.

Дополнительно доступны native smoke с установленными весами, Qt/WebEngine и публичным face fixture. Проверки включают связь отдельных процессов, права наблюдателя, устаревшие кадры, таймеры событий, SQLite, видеокодек и путь аккаунт → экзамен → ответы → база. В native workflow движения человека заменены явно обозначенной тестовой калибровкой; это проверка соединения компонентов, не точности глаз.

## Границы готовности

Реализованы локальный экзамен, раздельные состояния головы/глаз, наблюдение, события и записи. **Все требования ещё нельзя считать принятыми.** Остаются пропуски телефона, едва видимого над столом; реальные L/R/U/D глаз/головы и два человека требуют размеченного видео с целевой камеры. `PHONE_AIMED` — эвристика расположения/удержания телефона, не достоверная ориентация его объектива. Физические Windows-блокировки также требуют проверки.
